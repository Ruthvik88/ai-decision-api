# Development Log & AI Assistance Notes

This document provides an honest, factual record of how this project was developed using **Antigravity** (an AI coding agent) to scaffold and implement the codebase, alongside continuous human review, testing, and hands-on debugging.

---

## Technical Overview & Development Process

Antigravity was used to scaffold the repository architecture, create initial database models, implement FastAPI endpoints, build the Streamlit user interface, and draft the RAG pipeline. However, several real-world issues—ranging from corrupted initial data files to deprecated SDK endpoints and model quota constraints—required human diagnosis and intervention to reach a fully working state.

---

## Timeline of Issues Encountered and Resolved

### 1. Data File Extraction Error & Proposed Data Fabrication
- **Issue**: During initial local environment setup, archive extraction produced macOS Apple double resource fork metadata files (`._cancellations.md`, `._tickets.csv`, etc.) in place of actual policy markdown documents and data files.
- **AI Behavior**: The AI agent initially failed to recognize that the extracted files were empty metadata stubs and proposed fabricating placeholder policy text and fake ticket data instead of flagging the extraction failure.
- **Human Intervention**: Caught the error before building logic on top of fabricated rules. Instructed the agent to inspect the source files properly and unpack the genuine `knowledge_base/` markdown files and dataset.

### 2. Embedding Model Deprecation (`models/embedding-001` → `models/gemini-embedding-001`)
- **Issue**: Google deprecated `models/embedding-001` mid-project, causing text embedding requests in `src/retrieval.py` to return HTTP 404 errors.
- **Resolution**: Updated `embed_texts()` in `src/retrieval.py` to use `models/gemini-embedding-001`.
- **Verification**: Verified that the new 3072-dimensional vector output generated by `models/gemini-embedding-001` operated correctly with the NumPy cosine similarity matrix calculations without breaking chunk retrieval.

### 3. Generation Model Progression & Quota Limits
- **Progression**:
  1. `gemini-2.0-flash`: Hardcoded initially, but retired by Google, causing requests to fail or silently route to preview models.
  2. `gemini-3.6-flash`: Substituted as a replacement, but Google enforced a restrictive free-tier quota of only 20 requests per day for new projects, which caused HTTP 429 "quota exceeded" errors during iterative testing and batch evaluation.
  3. `gemini-3.5-flash-lite`: Adopted as the final working decision model. It provides sufficient daily free-tier quota while still achieving 100% accuracy (15/15) on `sample_test_cases.json`.
- **Evaluation Spacing**: Added configurable delay logic (`EVAL_DELAY_SECONDS`, defaulting to 6 seconds) to `evaluate.py` to prevent rapid test execution from exceeding per-minute request rate limits (RPM).

### 4. Stray Dependency & Version Conflict (`langchain-google-genai`)
- **Issue**: Running `pip install -r requirements.txt` failed due to a Pydantic version conflict introduced by `langchain-google-genai`.
- **Resolution**: The project does not use LangChain abstractions, relying instead on direct Google SDK calls and local NumPy calculations. Removing `langchain-google-genai` from `requirements.txt` resolved the dependency conflict.

### 5. Missing `import sys` in `evaluate.py`
- **Issue**: Running `python evaluate.py` triggered a runtime `NameError: name 'sys' is not defined` when attempting `sys.path.insert(0, ...)`.
- **Resolution**: Fixed by adding `import sys` directly to the top of `evaluate.py`.

### 6. Legacy SDK Usage (`google-generativeai` vs `google-genai`)
- **Note**: The project currently uses `google-generativeai` across `src/decision.py` and `src/retrieval.py`. Google has deprecated `google-generativeai` in favor of the unified `google-genai` SDK.
- **Status**: Kept as-is to preserve working implementation within project timelines. A full production refactor would migrate all API calls to `google-genai`.
